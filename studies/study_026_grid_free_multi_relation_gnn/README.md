# study_026_grid_free_multi_relation_gnn

## Status and research question

`draft`. Do separate source, receiver, CMP and full-offset neighbor relations improve
physical missing-trace reconstruction over matched untyped and single-graph controls?

The model uses additional complete labels from the canonical train partition
(`training_data.pool: all_train_traces`). Fixed training RMS and geometry origin are fitted
once on that pool. Benchmark target amplitudes enter scoring only. This information budget
differs from methods fitted only to the observed benchmark volume and must accompany every
comparison with Studies 022–025. Frozen inference performs no training or target-fitted scaling.

## Fixed inputs and evaluation

[inputs.yaml](inputs.yaml) owns dataset paths, partition and case identities, mask seeds and
available hashes. The existing seed-42 validation `random_trace` case is shared with
Studies 022–025. Its recorded mask hashes are copied from the existing case binding; this study
has not reverified the complete C3 files or measured that graph. The other three case identities
are fixed proposals with `not_prepared` and null hashes. Prepare and lock those inputs before
formal comparison; they are not silently generated by training or preflight.

The partition seed and validation/test masks stay fixed while training seeds vary over
42, 43 and 44. Both artificial `random_trace` and `random_whole_ffid` masks are used in training.
Whole-FFID masking hides every selected shot trace before dividing queries into batches.
Benchmark both mask kinds using their separate frozen cases. Test labels are not used for
checkpoint selection or changes to diagnostic bands.

The primary metric is physical target-only global S/N: sum reference and error energy over
all missing-query samples, then convert the ratio to dB. Report RMSE, relative L2, raw energy,
context counts, fixed time/offset/azimuth bands, zero fill and observed-only IDW alongside it.
Context-free queries remain in the main metric with a zero prediction. IDW is a separate
comparison and is never a model skip connection. Gate values are model diagnostics, not causal
importance scores. Query gate sums/counts are additive across batches; processed support/edge
counts are batch-instance totals.

## Configurations and comparisons

[config.yaml](config.yaml) is the learned-gate formal starting candidate. It fixes width 64,
two rounds, factor 2, eight neighbors per relation, 160/640 m relation scales and 1000 m
feature scales. Mask kinds have equal probability and missing fractions are 0.5/0.8.
It specifies 10,000 updates on time samples `[0,384)`; these are proposed conditions, not an
executed training budget. [config_smoke.yaml](config_smoke.yaml) uses two CPU updates and
samples `[64,128)`, preserving the model width and graph settings. The confirmed existing
validation smoke volume can restrict benchmark context and queries. Training still uses the
full canonical train partition; no unverified train crop is substituted.

All variants inherit the same pool, time, training seed, optimizer budget, codec, mask process,
evaluation metric and diagnostic bands. Frozen configs contain no model or training settings.

| Training config | Deliberate change | Fixed comparison |
|---|---|---|
| `config.yaml` | Learned relation gate | Four typed candidate relations |
| `variants/mean.yaml` | Equal mean across available relations | Same typed edges and value transform |
| `variants/plain_gcn.yaml` | `plain_gcn_row_normalized` | Same observed pair union, codec and labels |
| `variants/untyped.yaml` | One geometry-conditioned aggregation per unique pair | Same multi-relation candidate union |
| `variants/single_4d.yaml` | One exact 4D graph with k=32 | Same untyped model and common distance scales |
| `variants/without_{source,receiver,cmp,offset_azimuth}.yaml` | Remove exactly one relation | Remaining relation IDs and search rules |
| `variants/without_explicit_azimuth_features.yaml` | Zero derived sine/cosine/validity columns | Offset vector, length and topology retained |

The common untyped/single-4D distance uses midpoint and full-offset scales of 320/320 m.
The 32-neighbor cap matches the four-by-eight nominal edge budget; radius rejection and relation
overlap make actual unique-pair counts differ. Report measured typed/unique edge counts,
parameters, timing and memory. A coordinate renaming that produces the same graph is not a
separate method. The GCN is a row-normalized model on the masked directed graph, not a complete
reproduction of symmetric GCN. Removing derived azimuth features does not remove orientation
information carried by offset vectors and topology.

## Preflight and execution

Use the existing shared artifacts; these commands do not download or prepare data. From the
repository root, run the bounded preflight before deciding whether to launch a C3 smoke:

```bash
OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 PYTHONPATH="$PWD/src" \
python scripts/preflight_grid_free_trace_graph.py \
  --config studies/study_026_grid_free_multi_relation_gnn/config_smoke.yaml \
  --interim data/interim/c3_na/all_ffids \
  --processed data/processed/c3_na/c3_source_line_blocks_seed42 \
  --mask data/processed/c3_na/c3_source_line_blocks_seed42/masks/validation-random-trace-80-seed42 \
  --case data/processed/c3_na/c3_source_line_blocks_seed42/cases/c3_na_validation_random_trace_80_seed42 \
  --volume data/processed/c3_na/c3_source_line_blocks_seed42/volumes/c3_na_validation_smoke_t64_128_sl25_29_sh27_35_rx0_8_ry18_34 \
  --query-count 8 --query-limit 32 --device cpu --evaluate-baselines
```

The script calls the public preflight pipeline, which verifies artifacts and invokes
`run_trace_graph_preflight()`. It initializes an untrained model and fits scales on the fixed
training pool; it never constructs an optimizer. Exact search measures only the explicitly
requested first query IDs in stable order and reports those IDs. Full train-pool scale fitting
and artifact hashing are still required. The report includes input bindings/time, relation
empty rates, overlaps, support/edge counts, graph/read/forward time and measured resource peaks.
Process RSS and CUDA counters are lifetime peaks, not isolated-stage estimates.

Optional `--max-graph-seconds`, `--max-process-rss-bytes` and `--max-cuda-allocated-bytes` turn
exceeded or unavailable measurements into blockers. These are measured feasibility limits,
not memory reservations or a prediction of full-training cost. Missing files, changed hashes,
time mismatches and excessive query requests return a JSON `blocked` report and nonzero exit.
The runner does not change the crop, radius, support set or method to make a run pass.
With `--checkpoint`, use an `inference/*.yaml` config; model and scales then come exclusively
from that checkpoint. The preflight score covers its sampled queries only.

The following single-run example is provided for later use; it was not executed on C3:

```bash
rtg_run_id="$(date -u +%Y%m%dT%H%M%SZ)_$(git rev-parse --short HEAD)"
rtg_train_config=studies/study_026_grid_free_multi_relation_gnn/config_smoke.yaml
seis-interp train relational-trace-graph \
  --config "$rtg_train_config" \
  --interim data/interim/c3_na/all_ffids \
  --processed data/processed/c3_na/c3_source_line_blocks_seed42 \
  --validation-mask data/processed/c3_na/c3_source_line_blocks_seed42/masks/validation-random-trace-80-seed42 \
  --validation-case data/processed/c3_na/c3_source_line_blocks_seed42/cases/c3_na_validation_random_trace_80_seed42 \
  --validation-volume data/processed/c3_na/c3_source_line_blocks_seed42/volumes/c3_na_validation_smoke_t64_128_sl25_29_sh27_35_rx0_8_ry18_34 \
  --output "runs/study_026_grid_free_multi_relation_gnn/${rtg_run_id}_train_smoke" --device cpu --json

seis-interp interpolate relational-trace-graph \
  --config studies/study_026_grid_free_multi_relation_gnn/inference/validation_random_trace.yaml \
  --checkpoint "runs/study_026_grid_free_multi_relation_gnn/${rtg_run_id}_train_smoke/artifacts/best.pt" \
  --interim data/interim/c3_na/all_ffids \
  --processed data/processed/c3_na/c3_source_line_blocks_seed42 \
  --mask data/processed/c3_na/c3_source_line_blocks_seed42/masks/validation-random-trace-80-seed42 \
  --case data/processed/c3_na/c3_source_line_blocks_seed42/cases/c3_na_validation_random_trace_80_seed42 \
  --volume data/processed/c3_na/c3_source_line_blocks_seed42/volumes/c3_na_validation_smoke_t64_128_sl25_29_sh27_35_rx0_8_ry18_34 \
  --output "runs/study_026_grid_free_multi_relation_gnn/${rtg_run_id}_validation_smoke" --device cpu --json
```

For separately authorized formal runs, select `config.yaml` (training seed 42),
`seeds/seed43.yaml` or `seeds/seed44.yaml` individually. Keep the input paths and their hashes
fixed, choose a new immutable output, and omit the smoke volume when using the formal time
range. No script automatically launches three runs. Variants use the same formal budget;
resource calibration precedes any full comparison.

## Executed analytic smoke and remaining evidence

The CPU test in
[`test_relational_trace_graph_offgrid.py`](../../tests/integration/test_relational_trace_graph_offgrid.py)
completed three training updates for each mask kind, saved/reloaded best checkpoints and
predicted four arbitrary queries. The shared
[`analytic_trace_field.py`](../../tests/fixtures/analytic_trace_field.py) evaluates two Ricker
arrivals whose times and amplitudes are continuous functions of the actual CMP/full-offset
coordinates. Moving a query changes its independently evaluated ground truth. Observations
are irregular lists with unequal receiver counts; arbitrary-query inference has no `array_row`.
One query has no context and nonzero truth, and its error remains in the global metric.

This is an analytic function, not numerical wave propagation, real C3 or field data. The tiny
fixture uses width 8 and k=2 to test execution, not the full study model's performance. It checks
nonzero learned output, query-batch invariance and physical target-only scoring; no accuracy
threshold, paper result or SOTA claim is attached.

```bash
OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 pytest \
  tests/unit/test_grid_free_trace_graph_study.py \
  tests/integration/test_relational_trace_graph_offgrid.py \
  tests/integration/test_relational_trace_graph_preflight_run.py
```

Smoke artifacts are temporary pytest outputs: each off-grid case writes `best.pt`,
`offgrid_prediction.npy` and `offgrid_metrics.json` under its pytest temporary directory.
They are not formal study runs or committed results. No C3 preflight, C3 training/frozen
prediction, GPU calibration, three-seed comparison or wide-azimuth/field validation was run
for this study. Existing C3 metadata and the analytic smoke do not establish those results.

Promotion requires matching input information/case/time, all listed ablations, fixed-mask
multi-seed measurements and resource reporting. Wider grid-free claims additionally require
waveforms correctly generated or observed at irregular coordinates; relabeling regular-grid
waveforms with jittered coordinates is not valid evidence. C3 NA alone cannot establish
wide-azimuth or field generalization.
